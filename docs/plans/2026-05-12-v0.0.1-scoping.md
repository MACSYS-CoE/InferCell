## What this doc is

The canonical v0.0.1 plan. Covers scoping (what biology is in, what's out, why), architecture, data strategy, and the engineering roadmap. Single source of truth — the dated `2026-04-13-v1-minimal-demo.md` has been folded in here.

## Position in one paragraph

A closed-loop toy cell, syn3A-flavoured, three blocks: ODE metabolism, ODE bulk gene expression, SSA bursty regulator. Coupled by shared resource pools (ATP, NTPs, AAs) and by the fact that one expressed gene encodes a metabolic enzyme — so translation feeds back into metabolism, which fuels translation. ~10–15 free parameters, ~6–8 dynamic states. Inference is hybrid (NUTS where there's a likelihood, ABC-SMC where there isn't) with explicit posterior propagation across the ODE/SSA boundary. Validation in v0.0.1 is synthetic in two tiers; real syn3A data is v0.0.2+.

## Scoping decisions

| Axis | Choice | Reason |
|---|---|---|
| Target organism | syn3A | Smallest real genome → "minimal" framing is honest. Breuer/Thornburg give plausible kinetic ranges. Lilith's chromosome work extends naturally |
| Module set | Metabolism (ODE) + bulk GE (ODE) + bursty regulator (SSA) | Closed resource loop = minimum autocatalytic structure. Bursty SSA has no ODE equivalent → load-bearing case for hybrid inference |
| Number of genes | 3–5 named bulk genes + 1 bursty regulator | Enough for the loop to close (≥1 metabolic enzyme, ≥1 translation-machinery component). Few enough that NUTS at ~10–15 params is tractable |
| Spatial | None | RDME is post-v0.0.1 |
| Growth / division | None | Mass-balance only. No cell cycle |
| Data | Synthetic, two tiers (see below) | Real data forces premature commitments. Path to v0.0.2 is identified, not deferred indefinitely |

These choices answer the three positions on issue #6:

- **Karr-pruned syn3A (Tom):** retained — syn3A organism, Karr-style modular cut (metabolism + RNA + protein), pruned to one closed loop instead of 28 modules.
- **RNA SSA + central carbon ODE (Lilith):** retained — that *is* the metabolism block and the bursty piece. Adding bulk GE as an ODE block is what closes the loop into a cell rather than two coupled processes.
- **Karr-style models are hypothesis generators; pick experimentally closeable (Paul):** adopted as the validation philosophy — v0.0.2 commits to specific datasets where every modelled observable is measurable. v0.0.1 stays synthetic precisely so we don't lock in observables before knowing what the model can resolve.

## Architecture

```
                  ┌───────────────────────┐
                  │  Metabolism (ODE)     │
                  │  carbon → ATP         │
                  │  ATP + N → NTPs       │
                  │  ATP + C → AAs        │
                  └───────────┬───────────┘
                              │ shared pools (ATP, NTPs, AAs)
                              │ shared params (joint NUTS)
                  ┌───────────┴───────────┐
                  │  Bulk GE (ODE)        │
                  │  3–5 named genes      │
                  │  ≥1 metabolic enzyme  │  ← closes the loop
                  │  ≥1 ribosome part     │  ← gates TL capacity
                  └───────────┬───────────┘
                              │ Level 1: ODE posterior → SSA prior
                              │ Level 2: SSA posterior → ODE refinement
                  ┌───────────┴───────────┐
                  │  Bursty regulator     │
                  │  (SSA, ABC-SMC)       │
                  │  one low-copy gene    │
                  │  modulates a TX rate  │
                  │  in bulk GE block     │
                  └───────────────────────┘
```

The architectural claim — and the reason this is InferCell-shaped rather than CovertLab-shaped — is that posteriors propagate across the heterogeneous block boundary with explicit uncertainty. Every other WCM I'm aware of either commits to a single formalism or stitches blocks together with point estimates.

## Module specifications

### Block 1 — Metabolism (ODE)

- 4–6 reactions: carbon source uptake, ATP production, NTP synthesis, AA synthesis. Sinks driven by TX (NTP consumption) and TL (AA + ATP consumption).
- ~5 free rate constants, ~4 state variables (carbon, ATP, NTP, AA).
- Already prototyped: `src/models/light_metabolism.jl`.

### Block 2 — Bulk gene expression (ODE)

- 3–5 named syn3A genes. Required composition:
  - ≥1 metabolic enzyme (its protein concentration acts as a rate parameter in block 1 — closes the loop).
  - ≥1 ribosome / translation-machinery component (its protein concentration multiplies translation rates of all genes — gates capacity).
  - Remaining 1–3 genes: dummy reporters or housekeeping.
- Mean-field ODE on mRNA and protein per gene. ~6 free rates (k_tx, k_tl, γ_mRNA, γ_protein, plus enzyme-coupling stoichiometries).
- Existing TX/TL module is the starting point; needs the enzyme→metabolism feedback added.

### Block 3 — Bursty regulator (SSA)

- One low-copy gene with two-state (on/off) promoter. Bursts of mRNA during ON. Protein modulates one TX rate in block 2.
- ~5 free params: k_on, k_off, k_tx_burst, γ_mRNA, k_tl (γ_protein optionally shared with block 2).
- Specific syn3A gene identity is illustrative — we pick a plausible candidate (sigma factor, low-copy regulator) but do not claim quantitative fidelity. v0.0.2 commits to a specific gene once we identify a dataset.
- No ODE equivalent — the inherent discreteness of bursting is the load-bearing reason this block exists.

## Data strategy

### v0.0.1 — synthetic only, two tiers

**Tier A — synthetic twin.** Generate data from the v0.0.1 model with known parameters. Recover posteriors. Pass criteria: 90% CI covers ground truth for all params; chains mix; wall-clock under 1 hour on a single HPC node.

What Tier A shows: the boundary protocol works as a **computational technique**. NUTS-ODE and ABC-SMC-SSA can't be jointly composed in a single sampler — so the protocol isn't optional even in a twin. Conditioned SSA posteriors should be tighter than uninformed ones; the cut posterior should approximate what joint inference would produce if it were tractable. This is correctness, not yet science.

**Tier B — refit under mismatch.** Generate data from a *richer* generator — e.g. a metabolic network with 2–3 extra reactions, or stochasticity in block 1, or finite-volume effects in block 2 — then refit with the v0.0.1 model. Pass criteria: shared parameters (meaningful in both generator and fitted model) are recovered within their CIs; mis-specified parameters degrade in interpretable ways; the boundary protocol's uncertainty estimates remain calibrated.

What Tier B shows: the boundary protocol is **honest under model error**. This is the scientific claim. A pure twin can't surface it because by construction there's no error to be honest about. Tier B exists to demonstrate that conditioning the SSA block on the ODE posterior doesn't over-propagate false confidence when the ODE block is wrong.

We do not go further than Tier B in v0.0.1.

### v0.0.2+ — real syn3A data

Candidate datasets, in order of tractability:

1. **Breuer et al. 2019 (eLife)** — syn3A metabolite concentrations and flux measurements. Direct test of block 1. Likelihood: Gaussian on log-concentrations / fluxes. Most tractable starting point — data shape matches block 1 outputs directly.
2. **Hutchison et al. 2016 (Science) and follow-ups** — bulk RNA-seq, growth rates. Tests block 2 mRNA dynamics in aggregate. Requires committing to a likelihood for sequencing counts (NB / Poisson).
3. **Single-cell RNA-seq for bursting** — tests block 3 directly via distributional fit (mean + Fano + ideally full distribution). No canonical syn3A scRNA-seq dataset I'm aware of yet; revisit.

Each requires committing to (i) which observable, (ii) which likelihood, (iii) which noise model. We defer all three to v0.0.2 by design.

## Engineering roadmap

### Step 1 — Light metabolism module + shared parameters [DONE]

- New file: `src/models/light_metabolism.jl`. Solved shared-parameter design via `Vector{Int}` indices in `param_idxs`. `build_problem([TranscriptionTranslation(), LightMetabolism()])` produces a single ODEProblem.
- Tests pass; forward sim produces biologically reasonable trajectories.

### Step 2 — Joint ODE inference [DONE]

- `infer([txl, metab], data)` runs NUTS on the composed 5-state system. All ~8 parameters recovered at 90% CI from synthetic data. `ForwardDiffSensitivity` scales acceptably at this size.

### Step 3 — Level 1 boundary protocol [DONE]

- `KDEPrior <: ContinuousUnivariateDistribution` wraps KernelDensity.jl fits for use as ABC-SMC priors.
- `boundary_condition(chain, ssa_models; method=:kde)` builds conditioned priors from ODE posterior.
- `sequential_infer(ode_models, ode_data, ssa_models, ssa_data)` runs the full pipeline.
- Integration test shows SSA posteriors tighten vs uninformed.

### Step 4 — Level 2 boundary protocol (message-passing) [NEXT]

Close the loop so SSA posteriors feed back to refine ODE inference, enabling iterative convergence of the cut posterior.

- Iterative message-passing loop between ODE and SSA blocks.
- Convergence criterion (e.g. KL divergence between successive posteriors).
- Test: demonstrate convergence and improved parameter recovery over single-pass sequential conditioning.

### Step 5 — Close the v0.0.1 biology

Specific to the scoping decisions in this doc; these were *not* in the original v1 plan:

- Enzyme-production → metabolic-rate coupling: block 2's enzyme protein concentration enters block 1 as a rate parameter, closing the autocatalytic loop.
- Replace constitutive `StochasticGE` with a two-state bursty regulator in block 3.
- Assign specific syn3A genes to block 2 slots (cosmetic but worth committing to).
- Tier B generator: a "v0.0.1+ε" model with extra reactions for the synthetic mismatch experiments.

### Step 6 — End-to-end demo + figure

One script runs the full v0.0.1 pipeline and produces a publication-quality multi-panel figure:

- **(A)** Architecture schematic (hand-drawn or TikZ).
- **(B)** Joint ODE posteriors — blocks 1 + 2, ground truth overlaid.
- **(C)** Boundary protocol effect — SSA posteriors with/without ODE conditioning; bonus: Tier B mismatch plot showing calibration under model error.
- **(D)** Posterior predictive — forward simulations from the full pipeline posterior, data overlaid.

Done when: `examples/v0_0_1_demo.jl` runs end-to-end on one HPC node and produces the figure.

## AD backend: ForwardDiff → Mooncake migration

The SciML ecosystem is migrating from ForwardDiff.jl to [Mooncake.jl](https://github.com/compintell/Mooncake.jl) as the default AD backend. Mooncake is reverse-mode and should scale better at higher parameter counts (O(1) gradient cost vs ForwardDiff's O(n_params)). Relevant once we add Step 5's enzyme coupling and parameter count creeps further.

Action items (separate PR):

- Check Turing.jl + SciMLSensitivity.jl Mooncake support status.
- Benchmark ForwardDiff vs Mooncake on the joint composed system.
- If production-ready, switch `sensealg` default. Otherwise document the migration path and stay on ForwardDiff.

## Risks

| Risk | Mitigation |
|------|------------|
| Closed loop (block 2 → block 1) destabilises the ODE | Start with the enzyme coupling at low gain; verify forward sims; consider rate-limiting via Michaelis-Menten if blow-up |
| Bursty SSA inference is slow | Reduce particle count; parallelise across ODE posterior draws; if pathological, fall back to constitutive SSA for v0.0.1 and promote bursting to v0.0.2 |
| ForwardDiff too slow at ~15 params | Benchmark in Step 5. Fall back to adjoint methods or Mooncake |
| Tier B mismatch experiments take longer than expected | Tier B is the scientific claim — don't cut it. Cut Step 6's figure polish first |
| Level 2 convergence is noisy / hard to diagnose | Start with a strict KL-based criterion; widen if it never converges. Iterations capped |

## What's out (and why)

| Out of scope | Why | When it returns |
|---|---|---|
| Spatial / RDME | Engineering cost dwarfs the inference contribution at v0.0.1 | After Level 2 boundary works |
| Level 3 boundary protocol | Level 2 has to demonstrate value first | v0.1+ |
| DNA replication, chromosome | Needs spatial; needs cell cycle | v0.1+ |
| Cell cycle, division | Needs explicit volume / surface area dynamics | v0.1+ |
| Membrane, transport | Needs spatial | v0.1+ |
| Real data | Forces premature commitment to observable + likelihood | v0.0.2 |
| >10 genes | NUTS scaling and SSA cost; no extra architectural insight | When justified by a dataset |
| Population / mother-machine inference | Single-cell first; population is a separate inference problem | v0.1+ |
| Moment closure methods | ABC-SMC suffices for v0.0.1 SSA block | If SSA scaling bites |
| Neural posterior estimation (SBI) | ABC-SMC suffices; NPE is a backend swap, not new science | When ABC-SMC scaling bites |
| Model selection via Bayes factors | Strong narrative addition but not core to the architecture demo | v0.0.1+ nice-to-have |
